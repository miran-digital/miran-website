# راهنمای پشتیبان و بازگشت Miran Shop

## انواع محافظت موجود

1. **Checkpoint/Version سایت:** بازگشت کد به نسخه منتشرشده قبلی از Sites.
2. **Storefront Revision:** بازگردانی تنظیمات محتوایی فروشگاه از پنل مالک.
3. **D1 Logical Backup:** خروجی JSON تمام جدول‌های D1 از API مالک.
4. **R2 Media:** فایل‌های باینری تصویر، ویدئو، مدرک و فیش؛ داخل JSON قرار نمی‌گیرند.

## دریافت پشتیبان D1

مالک وارد `/admin` می‌شود و از بخش پشتیبان، خروجی JSON را دریافت می‌کند. خروجی
شامل Schema Version، زمان، تعداد و ردیف‌های جدول‌هاست. این فایل ممکن است اطلاعات
شخصی مشتری داشته باشد؛ آن را عمومی، ایمیل یا در Git ذخیره نکنید.

## بازگشت امن کد

1. نسخه هدف را در تاریخچه Sites مشخص کنید.
2. پیش از بازگشت، از D1 و R2 فعلی نسخه پشتیبان بگیرید.
3. نسخه کد قبلی را منتشر کنید؛ Migration معکوس یا حذف جدول اجرا نکنید.
4. صفحه اصلی، `/api/health`، ورود، سفارش‌ها و تعداد داده‌ها را کنترل کنید.

## بازگردانی تنظیمات فروشگاه

پنل مالک Revisionهای تنظیمات را نمایش می‌دهد. بازگردانی فقط State محتوایی ذخیره‌شده
را جایگزین می‌کند و محصولات/سفارش‌ها/مشتریان را حذف نمی‌کند. پیش از تأیید، زمان و
نسخه مقصد را کنترل کنید.

## بازیابی کامل D1

بازیابی کامل JSON باید ابتدا روی D1 آزمایشی، با Transaction و کنترل Count انجام شود.
تا زمانی که Restore Test برنامه‌ریزی‌شده (یکی از موارد تعویقی مالک) اجرا نشده، فایل
پشتیبان را مستقیماً روی Production Import نکنید. ترتیب امن:

1. ساخت D1 آزمایشی و اجرای Migrationها تا Schema Version فایل.
2. Import جدول‌ها با رعایت کلیدهای یکتا و بدون `DELETE` یا Reset.
3. مقایسه تعداد محصولات، دسته‌ها، سفارش‌ها، فروشندگان، تنظیمات و فایل‌های ارجاع‌شده.
4. آزمایش ورود، Checkout، پرداخت غیرفعال/فعال و دسترسی‌های خصوصی.
5. تنها پس از تأیید مالک، برنامه‌ریزی Maintenance و جایگزینی Production.

## R2

پشتیبان منطقی D1 فقط URL/Key فایل را نگه می‌دارد. نسخه‌برداری زمان‌بندی‌شده R2 و
Restore Test بخشی از مورد تعویقی Backup است. حذف Objectهای R2 برای بازیابی ممنوع است.
